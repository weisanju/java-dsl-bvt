# 架构冻结清单 v1（已确认）

> 目的：把已拍板的关键架构参数固定下来，避免后续开发反复讨论。

## 1. 访问与安全

1. **无登录模式**（平台内部使用，不做账号体系）。
2. **仅内网访问**（必须通过内网网段或 VPN）。
3. **入口层 IP 白名单**（建议在 Nginx/Ingress 层实现）。
4. API 触发接口建议保留 `Idempotency-Key`，避免重复触发 run。

## 2. 配置格式策略

1. 用例配置支持 **YAML / JSON** 双格式。
2. YAML **不允许高级语法**：
   - 不允许 anchor / alias
   - 不允许多文档（`---` 多段）
3. 服务端统一解析为 `normalized_definition(JSONB)` 执行。

## 3. 执行策略

1. **Fail-fast 范围：step 级**
   - 当前 step 断言失败后，立即终止当前 case。
2. **suite 级继续执行**
   - 单个 case 失败不终止 suite，其它 case 继续。

## 4. QLExpress 沙箱策略

1. 只允许白名单函数（如 `jsonPath`、`len`、`contains`）。
2. 禁止任意 Java 类访问和反射能力。
3. 表达式执行异常必须返回可读错误信息。

## 5. 资源与稳定性默认值

1. `step timeout`：**5000 ms**
2. `case timeout`：**60000 ms**
3. 请求/响应快照截断：**16 KB**
4. 运行结果保留周期：**90 天**

## 6. 调度与防重入

1. 定时计划采用数据库扫描（`@Scheduled`）。
2. 同一计划同一时间只允许一个实例运行（DB 锁防重入）。
3. 计划 misfire 处理：默认跳过过期窗口，不补跑。

## 7. TDD 门禁（冻结）

1. 核心引擎必须先写失败测试再写实现（Red -> Green -> Refactor）。
2. YAML/JSON 双格式必须有等价性测试。
3. 主链路（创建 case -> 执行 run -> 查询报告）必须有回归测试。
