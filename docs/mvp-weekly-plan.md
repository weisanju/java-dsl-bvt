# Java + Karate 接口测试平台 MVP 功能清单（按周排期）

## 1. 规划目标

- 在 8 周内交付一个可上线试点的接口测试平台 MVP。
- 支持 HTTP/HTTPS 接口测试，执行引擎采用 Karate。
- 覆盖「测试资产管理 -> 任务调度 -> 分布式执行 -> 报告分析 -> CI 集成」闭环。
- 能服务至少 2 个业务项目，形成可复用标准。

## 2. 团队与资源假设

- 后端开发：2 人
- 前端开发：1 人
- 测试开发（SDET）：1 人
- DevOps：0.5 人
- 部署环境：1 套测试环境（含 PostgreSQL、Redis、RabbitMQ、MinIO）

> 如实际人力不足，可将第 6-8 周内容拆成两期。

## 3. MVP 范围（本期必须完成）

1. 用户登录、基础 RBAC（项目级权限）。
2. 项目/环境/变量管理（支持密钥变量，避免明文展示）。
3. 用例管理（Karate 脚本 + JSON/YAML 测试数据集）。
4. 套件管理（用例编排、执行顺序、标签过滤）。
5. 执行中心（手动触发、定时触发、CI 触发）。
6. Runner 执行节点（拉取任务、并发执行、失败重试）。
7. 报告中心（通过率、失败明细、耗时、历史趋势）。
8. 审计日志与基础告警（企业微信/飞书 Webhook 二选一）。

## 4. 非目标（MVP 暂不做）

- gRPC/WebSocket 专项测试。
- 复杂链路压测（性能测试独立工具后续接入）。
- 多租户计费、组织级审批流。
- AI 自动生成用例。

## 5. 里程碑与按周排期

## Week 1：项目启动与技术基线

### 功能/任务
- 明确业务边界、角色权限模型、对象模型（项目/环境/用例/计划/执行）。
- 初始化后端工程（Spring Boot 3 + Java 21）与前端工程（Vue3 + TS）。
- 初始化基础中间件连接（PostgreSQL、Redis、RabbitMQ、MinIO）。
- 落地编码规范、接口规范、分支规范、发布流程。

### 交付物
- 《技术方案说明》V1
- 工程骨架可编译、可启动
- 基础 CI（构建 + 单测）流水线

### 验收标准
- 主分支可一键构建并通过基础 CI。
- 后端健康检查、数据库连通、队列连通正常。

---

## Week 2：账号体系与项目空间

### 功能/任务
- 用户、角色、项目、成员关系管理。
- JWT 登录与接口鉴权。
- 项目级权限（管理员/开发/测试/只读）。
- 审计日志框架（记录关键资源变更）。

### 交付物
- 认证授权 API
- 项目与成员管理页面
- 审计日志落表

### 验收标准
- 不同角色访问同一接口出现正确权限控制。
- 核心资源变更均可追溯操作者与时间。

---

## Week 3：环境与变量中心

### 功能/任务
- 环境管理（dev/test/staging）。
- 普通变量与密钥变量管理（密钥仅引用，不回显明文）。
- 变量作用域（全局/项目/环境）与优先级覆盖规则。
- Runner 侧变量注入规范。

### 交付物
- 环境与变量管理 API + 页面
- 变量解析组件（执行前渲染）

### 验收标准
- 同一用例可在多环境切换执行。
- 密钥变量不会在日志与报告中泄露。

---

## Week 4：用例管理（Karate + JSON/YAML）

### 功能/任务
- 用例实体管理：名称、标签、脚本类型、脚本内容、版本号。
- 支持关联 JSON/YAML 数据集（多数据驱动）。
- 支持从 OpenAPI 导入接口定义（基础版）。
- 提供在线调试执行（单用例 dry-run）。

### 交付物
- 用例 CRUD API + 页面
- 数据集管理 API + 页面
- 单用例调试能力

### 验收标准
- 可创建并保存 Karate 脚本。
- 可读取 JSON/YAML 数据集并完成参数化执行。

---

## Week 5：套件编排与执行中心（V1）

### 功能/任务
- 套件管理：纳入多个用例、排序、按标签过滤。
- 任务触发：手动执行、CI Webhook 触发。
- 构建执行上下文（项目 + 环境 + 变量 + 套件版本）。
- 引入任务状态机（queued/running/success/failed/cancelled）。

### 交付物
- 套件管理 API + 页面
- 执行触发 API（手动/CI）
- 执行记录列表页

### 验收标准
- 单次触发可生成完整 run 记录并可追踪状态变化。
- CI 可通过 API 成功触发指定套件执行。

---

## Week 6：调度与 Runner 分布式执行

### 功能/任务
- 定时调度（Cron），支持暂停/恢复计划。
- Runner 注册与心跳机制。
- 任务分发（RabbitMQ）与并发执行。
- 失败重试策略（网络异常可重试，断言失败默认不重试）。

### 交付物
- 调度服务（计划任务）V1
- Runner Agent V1（可容器化部署）
- 失败重试机制

### 验收标准
- 至少 2 个 Runner 并行执行同一批任务。
- 在 Runner 异常下线后，任务可重新分配。

---

## Week 7：报告中心与通知

### 功能/任务
- 汇总执行结果：通过率、失败率、平均耗时、P95 耗时。
- 失败明细：请求/响应快照、断言失败信息、错误堆栈。
- 历史趋势图（按计划/套件/项目维度）。
- 通知能力（飞书/企微 Webhook）。

### 交付物
- 报告 API + 页面
- 通知模板与触发规则
- 结果归档到 MinIO

### 验收标准
- 每次 run 执行后 1 分钟内可查看完整报告。
- 失败任务可自动推送摘要通知（含跳转链接）。

## Week 8：联调、压测、试点上线

### 功能/任务
- 端到端联调与缺陷收敛（平台 + Runner + CI）。
- 数据库索引优化、接口性能优化、监控告警完善。
- 编写运维手册、用户手册、故障排查手册。
- 选 2 个业务项目试点并完成迁移。

### 交付物
- MVP 发布版本（v1.0.0）
- 试点复盘报告（问题与二期建议）
- 监控大盘与告警规则

### 验收标准
- 关键链路可用性 >= 99.9%（试点期间）。
- 试点项目核心回归用例可稳定每日执行。

## 7. 风险与应对

1. **风险：并发执行数据互相污染**  
   应对：测试数据命名空间隔离；环境变量分层；执行前自动准备/清理。

2. **风险：Runner 不稳定导致任务积压**  
   应对：心跳超时摘除、任务回收重派、队列堆积告警。

3. **风险：报告数据量增长快**  
   应对：冷数据归档到对象存储；数据库仅保留索引与摘要。

4. **风险：密钥泄露**  
   应对：密钥字段加密存储；日志脱敏；权限隔离与审计。

## 8. 验收基线（Definition of Done）

- 业务团队可独立创建项目、环境、用例、套件并发起执行。
- CI 能自动触发回归并回传结果链接。
- 报告可定位失败原因（请求、响应、断言、错误堆栈）。
- 运维可监控服务健康、队列积压、Runner 状态。
- 文档齐全（接入、使用、运维、排障）。
